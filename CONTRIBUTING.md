# Разработка

Изменения должны решать одну понятную задачу и содержать достаточно контекста для человека, который не видел переписку.

## Рабочий процесс

1. Создать короткую ветку от актуальной `main`: `feat/touch-controls`, `fix/save-recovery`, `docs/android-setup`.
2. Внести связанное изменение. Не смешивать функцию, массовое форматирование и обновление зависимостей в одном PR.
3. Запустить подходящие проверки. Для текущих инструментов: `pwsh -NoProfile -File ./tools/verify-project.ps1`.
4. Открыть PR с описанием проблемы, результата и фактически выполненных проверок.
5. Дождаться CI, разрешить обсуждения и выполнить squash merge. Рабочая ветка удаляется автоматически.

`main` защищена: изменения через PR, обязательный `Verify repository`, актуальная база, линейная история, запрет удаления и force push. В проекте один сопровождающий, поэтому дополнительное одобрение второго человека не требуется.

## Коммиты

Используем [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/):

```text
type(scope): imperative summary

Why this change is needed and what behavior it changes.
Mention validation or a relevant tradeoff when useful.

Closes #123
```

Заголовки коммитов и PR пишем по-английски, до 72 символов, с конкретным действием. Описание PR может быть на русском. Допустимы `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`; scope необязателен. `!` обозначает несовместимое изменение.

| Тип | Когда использовать | Пример |
| --- | --- | --- |
| `feat` | Новое поведение | `feat(gameplay): add touch movement` |
| `fix` | Исправление ошибки | `fix(save): preserve progress after resume` |
| `perf` | Измеримое ускорение | `perf(render): batch static background sprites` |
| `refactor` | Перестройка без изменения поведения | `refactor(input): isolate touch mapping` |
| `docs` | Документация | `docs(setup): clarify Android SDK requirements` |
| `ci` / `build` | CI или сборка | `ci(checks): cancel superseded pull request runs` |
| `chore` | Обслуживание проекта | `chore(deps): update development tooling` |

Не использовать `update`, `fix stuff`, `wip` и номера итераций без объяснения результата. Не обозначать обычную настройку как новую функцию игры. Не дописывать вымышленные измерения, тесты или сведения о релизе.

Проверка заголовка локально:

```powershell
pwsh -NoProfile -File ./tools/check-commit-message.ps1 -Message 'fix(save): preserve progress after resume'
```

CI проверяет заголовок PR; при squash он становится заголовком итогового коммита. Уже опубликованную историю `main` не переписываем.

## Проверки и зависимости

- Проверять поведение, которое затронуто изменением. Для документации достаточно проверки ссылок и diff; для сохранений и игрового состояния нужны проверки сценариев, включая прерывания.
- Разделять «скрипт прошёл», «APK собран» и «игра проверена на Android». В PR указывать достигнутый результат.
- В CI нет установки Android SDK, эмулятора или зависимостей игры до выбора движка. Текущий job выполняет только проверки исходников и соглашений.
- Внешние GitHub Actions закреплены по полному SHA. Dependabot предлагает их обновления отдельными PR.
- Импортированные скиллы сохраняют исходные байты. При осознанном обновлении проверить источник и лицензию, затем обновить `skills-provenance.json` вместе с файлами.
- Файлы больше 10 MiB не добавлять напрямую в Git: использовать Git LFS или отдельное хранилище. CI проверяет размер файлов и исключает приватные/генерируемые пути из индекса.

## Публичный репозиторий

Проверять staged diff перед отправкой. Конфигурация машины, `.env`, ключи подписи, SDK, APK и device-артефакты хранятся вне Git. Оригинальные арты добавлять с указанием происхождения и прав на использование. Для уязвимостей использовать [SECURITY.md](SECURITY.md).
