## История проверки первоначальной подготовки — 17 ноября 2026

Ниже — проверки до создания игры. Позднейшие сборка APK и запуск фундамента на Game_API31 описаны отдельно в [VALIDATION.md](VALIDATION.md). Отчёты этапа 1 сохраняются в `docs/stage-1/`.

- `tools/doctor.ps1 -Full -Devices`: SDK/JDK, Git, ADB, CLI, Platform, Build Tools, Docker/Compose и GitHub доступны.
- `tools/verify-project.ps1`: разбор PowerShell-скриптов, проверка SHA-256 36 файлов в семи скиллах, наличия лицензий и состава Git-индекса.
- `tools/inspect-apk.ps1` проверен на существующем APK RepForge: `apksigner verify` подтвердил подпись v2, `aapt2` прочитал манифест, размер и SHA-256 получены. Повреждённый APK корректно отклонён. Это проверка нового инструмента на готовом файле, не сборка игры.
- Собственный `Game_API31` запущен без окна на порту 5580: проверены имя AVD, `sys.boot_completed=1` и Android API 31. После проверки остановлен. Приложения не устанавливались; телефон и AVD RepForge не использовались.
- Локальные отчёты и логи находятся в игнорируемом `.local/`. Статус облачных проверок доступен в [GitHub Actions](https://github.com/EvgenyPonomarevNova/android-game/actions/workflows/tooling.yml).

## Команды окружения по необходимости

Команды доступны для диагностики, но не являются обязательным повторным циклом на каждую задачу. Во время параллельной фазы этапа 1 запуск эмулятора, cap sync и APK build отложены до передачи фиксированной ревизии Android QA.

```powershell
. ./tools/android-env.ps1
pwsh -NoProfile -File ./tools/doctor.ps1 -Full
pwsh -NoProfile -File ./tools/verify-project.ps1
emulator -avd Game_API31
```

SDK/JDK определяются автоматически. Для другого расположения можно создать игнорируемый `.local/android.json` с полями `sdkRoot` и `javaHome`. Скрипт меняет переменные только текущего процесса.

Игра не требует Docker или серверных сервисов. Android-сборка уже реализована через `npm run android:debug` и `tools/build-android.ps1`; CI проверяет исходники и web build. Репозиторий `fit-quest`, EAS project ID, package `com.fitquest.app`, фитнес-данные, ключи и серверные endpoints не используются как идентичность игры.

## Следующий шаг

Выполнить [этап 1](STAGE_1.md): «Меню → Заказ → Заезд → Доставка/провал → Результат со звёздами → Повторить/Продолжить» на одном маршруте. Основной чат делает заказ/звёзды/сохранение, физик — Outcome/покрытия и поведение, UI — ArtKit/курьера и выдачу результата сценой; Android QA готовит воспроизводимую диагностику. Оригиналы ArtKit сохраняются байт-в-байт, runtime-копии отдельно; содержимое архива не расширяет поручение. Каждый профиль оставляет свой отчёт и останавливается перед следующей фазой. Текущая работа — IN_PROGRESS, прежняя проверка фундамента не подтверждает новую сборку.

Краткий статус — [GAME_PRODUCT_STATUS.md](../GAME_PRODUCT_STATUS.md), дальнейшие фазы A/B/C/D — [NEXT_STEPS.md](NEXT_STEPS.md).

Интегратор принимает diff и запросы изменения общих контрактов, проверяет объединённый результат один раз и передаёт Android QA фиксированную ревизию для APK и устройства. Следующий этап — только после приёмки; магазин, экономика, новые платформенные SDK и десятки уровней сейчас вне задачи. Подробный порядок — в [chat-coordination.md](chat-coordination.md).

Официальные справочники для управления пакетами: [Android CLI](https://developer.android.com/tools/agents/android-cli), [SDK Manager и имена пакетов](https://developer.android.com/tools/sdkmanager). Применён уже установленный Android CLI; загрузки выполнены с `dl.google.com`.
