# Roadmap «Не Разлей!»

17 ноября 2026. Фундамент создан; его прежняя проверка зафиксирована в [VALIDATION.md](VALIDATION.md). Активный этап — **IN_PROGRESS**, один coffee vertical slice: «Меню → Заказ → Заезд → Доставка/провал → Результат со звёздами → Повторить/Продолжить».

[STAGE_1.md](STAGE_1.md) — единственная доска задач и точных границ текущего этапа. Этот roadmap задаёт порядок развития; он не разрешает профилям самостоятельно начинать будущие фазы. Статус продукта — [GAME_PRODUCT_STATUS.md](../GAME_PRODUCT_STATUS.md), порядок интеграции — [chat-coordination.md](chat-coordination.md).

## A — Gameplay Polish

Довести один маршрут с кофе до понятного законченного цикла: управление скутером, покрытия, повреждения, доставка и причины провала, заказ, звёзды, сохранение лучшего результата, повтор/продолжение. Настроить читаемую обратную связь и баланс, сохраняя fixed-step Planck и независимость Simulation от UI.

Текущие владельцы: физик — Outcome/покрытия, основной чат — заказ/звёзды/сохранение, UI — выдача исхода сценой и визуальная обратная связь. Приёмка: полный цикл воспроизводится, исход выдаётся один раз, проверки объединённого кода проходят, затем подтверждается запуск конкретного APK. Новые изменения ещё не приняты.

## B — Visual Production

Производственная подготовка раздельных артов: курьер, скутер/колёса, груз, двор, UI, анимации и звук с установленным происхождением. Сохранить оригиналы, подготовить runtime-экспорты, согласовать якоря с физическими телами, проверить читабельность HUD и touch-кнопок.

В этапе 1 уже разрешена ограниченная часть B — подключение предоставленного ArtKit к одному маршруту. Полное визуальное производство идёт после приёмки slice. Приёмка: независимые физические тела отображаются корректно, ресурсы локальные, UI интерактивен, нагрузка измерена на целевом Android.

## C — Game Progression

После приёмки A/B: 20–30 уровней с постепенным обучением и ростом сложности, другие грузы с различающимся поведением, улучшения транспорта и сохранение прогресса. Сначала согласовать модель данных и баланс, затем наполнять LevelData небольшими проверяемыми партиями.

Эта фаза пока не начата и не входит в текущий этап. Критерии следующего задания уточняются до реализации; наличие roadmap не разрешает сейчас добавлять магазин, экономику или десятки уровней.

## D — Release

Проверить на реальном среднем смартфоне frame time и длительную сессию, аппаратный мультитач, safe area/жесты, блокировку, аудиопрерывания, холодный офлайн-запуск и восстановление сохранений. Показатели эмулятора не переносить на телефон; 60 FPS подтверждать измерением.

Утвердить постоянный applicationId, release-подпись вне Git, версионирование и материалы выбранного магазина. Подготовить нужный APK/AAB и отчёт по точному артефакту: размер, SHA-256, подпись, устройство и пройденные сценарии. Release-публикация и сторонние SDK требуют отдельного задания; debug APK фундамента не является релизом.

Переход между фазами — после приёмки результата координатором. Сначала профильные отчёты, затем единая проверка интегратором, после неё фиксированная ревизия Android QA; сборка каждой промежуточной правки не требуется.
