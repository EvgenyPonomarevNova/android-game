# Архитектура прототипа

## Карьера и конфигурация транспорта / Sprint03

Progression.ts содержит сериализуемые CareerState/VehicleSetup/RewardReceipt. Career.ts — чистые операции награды, покупки, бесплатного выбора, установки и навыков; цены/пороги в config/career.ts, контракты и условия открытия в content/contracts.json. Репутация рассчитывается по лучшим результатам разных контрактов, а не по числу попыток. Разовые milestone keys, bounded repeat/record bonuses и processedRuns защищают от повторной выдачи. Пользовательское оформление корпуса — отдельные купленные PaintId, без физических бонусов.

App последовательно исполняет транзакции: читает последний успешно сохранённый снимок, применяет чистую операцию, пишет целый SaveData и только затем обновляет React/saveRef. Монеты, инвентарь, установка, награда и рекорд не пишутся раздельно. Ошибка записи не показывает фиктивную покупку; результат можно сохранить повторно с тем же ключом идемпотентности. Черновые заезды не вызывают карьерное начисление.

Bridge.configureSetup делает копию выбранного транспорта/деталей/навыков/окраски. Сцена передаёт её Simulation при создании мира, а checkpoint сохраняет её. Pure-data Tuning.ts используется UI для сравнения параметров и симуляцией для реальных WheelJoint/мотора/сцепления/крепления; React не обращается к Planck. Температура горячего заказа зависит от игрового времени и теплоизоляции; пауза не охлаждает еду. Измеренные cleanLandings/balancedSections открывают навыки, включение явно выбирается в профиле.

LevelCatalog содержит две встроенные миссии плюс валидные published JSON. Contracts связывает levelId с сюжетом/наградой/условием доступа; UI заказа общий. Новые миссии не требуют нового React-экрана. Схема уровня поддерживает wet-asphalt, rain-evening и hot-meal с правилами температуры. Seed-генератор остаётся инструментом черновиков и не публикует случайную трассу автоматически.

## Поток данных

React создаёт один `GameBridge` и один `GameController`. Контроллер владеет Phaser и переключает Boot → MainMenu / Gameplay. Пауза и настройки принадлежат React; отдельная Pause-сцена не нужна. При выходе Gameplay освобождает мир и подписки, ввод сбрасывается. Размонтирование GameHost уничтожает Phaser, платформенные подписки и аудио.

`GameBridge`: типизированные команды start/pause/resume/restart/menu/checkpoint и события mode/telemetry/damage/result/error. MissionState передаёт компоненты груза, ветку, падения и доступность продолжения. selectLevel задаёт данные выбранного маршрута для следующего заезда; UI не обращается к Planck. `InputController` хранит источники клавиш и указателей отдельно; отпускание одного пальца не сбрасывает другой. Pointerup/cancel, lostpointercapture, blur и уход в фон освобождают управление.

HUD получает снимок раз в 100 ms. На каждом кадре React не обновляется. Phaser меняет только отображение; Arcade и Matter не подключены. Будущие реклама/платежи/авторизация добавляются за `PlatformAdapter`, не в Simulation.

## Физика

`Simulation` не импортирует Phaser, React или Capacitor. `PhysicsWorld`: один Planck World, шаг 1/60 s, накопитель максимум 100 ms и 6 шагов, solver 10/6. При долгом пропуске время отбрасывается; симуляция замедлится вместо неограниченной догонки. Пауза очищает накопитель; возобновление не симулирует время фона.

Метры, килограммы, секунды, Y вверх. Рендер: 60 px/m, Y и угол инвертированы; `BodyView` интерполирует предыдущую и текущую позы. Нечисловые координаты отклоняются. Контакты только накапливают данные; мутации через `defer` — после разблокирования solver. Удаление мира — вне шага.

Скутер: chassis с геометрией руля, два физических колеса, два WheelJoint, задний мотор. Тормоз затем включает задний ход; наклон ограничен моментом/угловой скоростью. `Vehicle` — контракт следующего транспорта, `SCOOTER` — типизированные параметры. Собственные части не сталкиваются друг с другом.

Кофе — отдельное тело и мягкий WeldJoint к багажнику. Урон от контактного импульса ограничен входящей относительной скоростью, чтобы статическая опора не считалась ударом; отдельно учитывается изменение скорости с поправкой на гравитацию. Пороги в `COFFEE`. События cargo:damaged, cargo:critical, cargo:destroyed детерминированы; последние два однократны. Это основа, не гидродинамика жидкости.

`Simulation.outcome` задаёт единственный терминальный исход: delivered, cargo-destroyed, cargo-rejected, overturned или out-of-bounds. Переворот требует устойчивой опоры, небольших скоростей и выдержки; вращение в воздухе само по себе не завершает заезд. `finished` означает любой терминальный исход. Последующие шаги остановлены. Покрытия LevelData.surfaces меняют трение в точке контакта непрерывной Chain; их же читает renderer.

`Orders.ts` содержит правила заказа и медалей; React показывает OrderScreen/ResultScreen. Успех оценивается в бронзу/серебро/золото (совместимые stars 1–3), провал — в 0. Рейтинг репутации не реализован. Дедлайн и пороги берутся из LevelData.difficulty. Рекорд сравнивает медаль, сохранность и время; необязательные medal/checkpointUsed/falls совместимы с Save v1. Старые кофейные ключи остаются отдельными. Повтор создаёт новую Simulation; возврат с результата открывает заказ.

Для груза surprise одно физическое тело несёт две независимые сохранности: cake (вес оценки .6) и drinks (.4), с разной реакцией на измеренные нагрузки. Общая integrity — взвешенная сумма. Checkpoint — отдельная явная команда: после достигнутой безопасной точки допускается одно продолжение физического падения. Simulation пересоздаёт мир и актёров, сохраняет elapsed/падения/тик, списывает ровно 15 п.п. суммарной сохранности и ограничивает медаль бронзой. EventBus остаётся тем же, Gameplay заново создаёт BodyView и сбрасывает визуальную реакцию. Второе продолжение запрещено; ниже порога доставки или после дедлайна оно недоступно.

`LevelData`: старт/финиш, цепочка поверхности с adjacency, препятствия, груз, сложность, sections, platforms, fork и checkpoint. Нижний ground и верхние платформы — самостоятельная физическая геометрия, oneWay допускает проход снизу. fork классифицирует траекторию, не телепортирует и не выбирает за игрока. `validateLevel` проверяет структуру, конечные числа, монотонные полилинии, диапазоны и пороги до создания тел; всё сериализуется в JSON.

`LevelAuthoring` собирает ограниченные секции по seed, при необходимости переносит физический шаблон развилки основной миссии. Это генератор черновиков, не доказательство проходимости. `LevelDocument` содержит schemaVersion/status/generation/level; мастерская ?editor=1 валидирует импорт, рисует профиль, хранит черновик отдельно и запускает обычную Gameplay без записи игровых рекордов. `LevelCatalog` подхватывает published JSON из src/content/levels; некорректный файл выдаёт диагностику и не ломает базовую миссию. CLI использует тот же модуль через существующий Vite SSR loader, без новых зависимостей; запись файлов только с exclusive create.

## Рендер и ресурсы

Canvas под React, размер следует viewport; zoom использует базу 1280×720 без растяжения. Камера экспоненциально следует за интерполированной позой, добавляет ограниченное упреждение и имеет границы. Дорога/город строятся один раз. Буфер Phaser 4 не умножается на devicePixelRatio: это сознательное ограничение нагрузки. Дорогих постоянных эффектов нет.

AssetLoader: image/atlas/fonts, loaderror и missing-texture fallback. Phaser позволяет позднее добавить Sprite, Animation, particles и слои с scrollFactor для параллакса. Onest (кириллица и латиница) локальный. AudioManager — единственный владелец звука; Phaser настроен с noAudio:true. Он загружает локальные OGG/WAV AudioKit через Web Audio после первого жеста, кэширует буферы, смешивает три слоя двигателя и переключает музыку с crossfade. AudioAssets.ts содержит типизированные ключи/пути/шины из манифеста набора. Музыка и SFX используют существующие независимые переключатели и общую громкость SaveService. Пауза приостанавливает AudioContext с сохранением позиции циклов; уход в фон требует следующего жеста/явного продолжения. Поколение заезда отменяет запоздалую загрузку SFX, cooldown ограничивает повторы, dispose освобождает источники и контекст.

## Хранилище и прерывания

Android: Preferences, Web: localStorage через StorageAdapter. SaveService: schema v2, миграции v0/v1 с сохранением старых settings/results, последовательные записи, неизменяемые снимки и последняя корректная резервная копия. Существующее прохождение нового контракта изv1 однократно переводится в карьерные milestones; старые кофейные ID не удаляются. Более новая версия не перезаписывается. Некорректные поля нормализуются, невозможная экипировка заменяется штатной; отсутствующий объект карьерыv2 считается повреждением и запускает восстановление backup. Ошибки записи видны пользователю. Настройки и результат пишутся по событиям, не по кадрам.

Visibility/blur и native appStateChange ставят паузу; возврат требует явного продолжения. Android Back: пауза в игре, продолжение в паузе, возврат из подэкранов, сворачивание из меню. WebGL contextlost ставит паузу; после восстановления можно продолжить или перезапустить. Потеря GPU и прерывания аудиофокуса на телефоне требуют отдельной проверки.

Веб-адаптация 0.4.1 расширяет настройки без смены Save v1: независимые уровни music/effects/engine, левосторонняя раскладка и масштаб кнопок, shake/hints. Старые значения sound/music/volume сохраняются. FPS overlay разрешён только DEV. AudioManager создаётся внутри setup эффекта App; Fast Refresh не может повторно использовать disposed-экземпляр. После первого жеста новый менеджер создаёт собственный AudioContext; шины применяют общую и индивидуальную громкость. Это архитектура; фактические веб/Android-проверки каждой версии раздельно описаны в профильном QA.
