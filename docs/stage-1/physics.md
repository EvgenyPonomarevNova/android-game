## Что исправлено и почему

1. Стоящий скутер не засыпал: `applyTorque(0, true)` будил Planck island на каждом тике. Нулевой наклон больше не вызывает torque; после стоянки тела спят, сохраняют положение и просыпаются от газа.
2. Газ + тормоз при скорости выше лимита отключали двигатель, включая торможение. Тормоз имеет приоритет; окончательное включение мотора вычисляется один раз. На точном лимите (`>=` / `<=`) тяга отключается без чередования enable/disable в одном вызове.
3. Постоянная опорная нагрузка на перевёрнутый стакан считалась новым ударом каждый тик: в воспроизведении сохранность падала 100 → 0 за 0,5 с после небольшого опускания к земле. Теперь pre-solve измеряет относительную нормальную скорость точек контакта, post-solve ограничивает ударный сигнал этой скоростью. Покой сохраняет 100%; реальные столкновения и перегрузки по-прежнему повреждают груз.
4. Добавлены терминальные исходы. `PhysicsWorld` корректно обрабатывает паузу из after-step: не продолжает catch-up, не делает отрицательным аккумулятор, сохраняет `alpha = 1`. Поза, время и тики на исходе совпадают при 30/60/120 render FPS, в том числе когда исход попадает на первый из двух тиков кадра.
5. Добавлены материалы дороги с разным сцеплением. Одна непрерывная Chain сохранена; коэффициент контакта определяется по X точки касания и обновляется в pre-solve. Возврат с гравия на асфальт восстанавливает сцепление того же колеса.

## Контракт для сцены, UI и интегратора

Из `src/game/core/Simulation.ts` экспортируется:

```ts
type RaceOutcome =
  | { success: true; reason: 'delivered' }
  | {
      success: false;
      reason: 'cargo-destroyed' | 'cargo-rejected' | 'overturned' | 'out-of-bounds';
    };

sim.outcome: RaceOutcome | null;
```

До исхода `outcome === null`, `finished === false`. Любой исход устанавливается один раз; `finished === true` теперь означает завершение как успехом, так и провалом. Для результата читать `outcome.success` и `outcome.reason`, а не трактовать любой `finished` как доставку. `cargo.delivery` становится `delivered` только при успехе; при любом провале — `failed`. Остаток кофе сохраняется фактическим: переворот/выезд за мир/отклонённая доставка не подменяют его нулём.

Приоритет одного fixed tick: `out-of-bounds` → `cargo-destroyed` → выдержанный `overturned` → финиш (`delivered` либо `cargo-rejected`). Успех: прежняя зона финиша по X, отклонение по Y < 2 м и сохранность >= `minimumIntegrity`. При меньшей сохранности вход в финиш завершает заезд провалом. `targetSeconds` остаётся ориентиром, не таймером поражения.

Терминальный исход вызывает `physics.setPaused(true)`; последующие `advance()` возвращают 0. Новый заезд — новая `Simulation`, как раньше. Сигнатуры Vehicle/Simulation, единственный Planck world и fixed-step сохранены. Новых событий GameBridge не добавлено. **Интегратору необходимо подключить все причины к сцене/экрану результатов и учитывать success при сохранении результата.** Эти файлы этому профилю не принадлежали.

## Формат покрытий

`LevelData.surfaces?: SurfaceRange[]`, где `SurfaceRange = { from: number; to: number; type: 'asphalt' | 'gravel' }`. Координаты — мировые метры по X, диапазон `[from, to)`. Диапазоны упорядочены, не пересекаются и лежат внутри X-границ ground; пустоты и отсутствие массива означают асфальт. Старые уровни валидны.

Из `src/game/levels/testLevel.ts` доступны `SURFACES`, `SurfaceType`, `SurfaceRange`, `surfaceAt(level, x)`. Коэффициенты поверхности: asphalt = 1, gravel = 0.35; контакт смешивается с материалом колеса по `sqrt(surfaceFriction * wheelFriction)`. На первом маршруте: асфальт [-15, 20), гравий [20, 26), асфальт [26, 80). Графика может читать те же диапазоны для отображения дороги.

Для переворота требуется опора шасси или стакана на статическую поверхность: контакт активен, не sensor, нормаль поддержки имеет Y > 0.5. Касание стены и переворот в воздухе сами по себе не дают провала. Потеря устойчивости или опоры сбрасывает выдержку. Вращение остаётся управляемым в воздухе; встречный наклон работает и выше лимита угловой тяги.

Лимиты отключают тягу, не обрезают физическую скорость от склона/столкновения. Модель кофе — пороговые удары и перегрузки, не симуляция жидкости; устойчивый переворот является отдельным правилом заезда. Физические размеры не подгонялись под изображения ArtKit. Проходимость первого маршрута подтверждена; субъективный баланс требует ручного плейтеста.
